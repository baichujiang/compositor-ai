# Compositor AI：Claude Code 与 Gemini CLI 扩展计划

日期：2026-10-11  
状态：Gemini 已按用户 2026-10-11 指令进入 v0.3.0 实现；Claude Code 继续暂缓。下面原始方案保留为设计记录，实际接入以仓库代码及使用说明为准。  
基线：Compositor AI v0.1.0，`ai/integrated-assistant` 分支。  
项目：[baichujiang/compositor-ai](https://github.com/baichujiang/compositor-ai)

最初要求仅记录方案。用户现已授权接入 Gemini；此次只实现统一后端基础和 Gemini，尚未授权实施 Claude Code。当前应用为 Compositor AI v0.3.0，原生基线仍为 Compositor 1.4.8。

实际实现：`AIBackend`、`AIBackendProvider`、`AIPlanningContract`、`AIGeminiCLIBackend`、`AIProcessRunner`，以及原 AI 面板中的后端选择和独立路径/模型设置。两种后端共用 `AIEditorCommands`，不改原生工具、布局、快捷键和文件格式。

Gemini 要求稳定版 CLI 0.63.0 或更新版本，JSON 外层和内层严格分开解析；最多一次格式修正，整体 180 秒，拒绝未知字段/类型/命令、过期文档及不合法编辑序列。切换后端清空应用对话与待执行计划，不自动切换其他服务。

配置校验按官方 0.63.0 实测修订为私有临时工作区：普通用户写的系统配置会被 CLI 忽略。用户文本中的 `@` 编码为 JSON 数据，只有应用生成的 PNG 使用显式文件引用。官方 CLI 配置、工具注册和 PNG 预处理已离线核对；真实 Gemini 登录下的编辑和看图效果仍待验证。CLI 自己可能保留会话或日志，不能将应用内存聊天等同于全部数据不落盘。

下文为原始设计计划：

## 1. 目标与实施顺序

让用户在同一个 AI 面板中选择 Codex、Claude Code 或 Gemini CLI。不同后端共用图层信息、画布预览、编辑命令、文档检查和原生撤销机制。

推荐实施顺序：先提取统一接口并验证 Codex，再接 Claude Code，最后接 Gemini CLI。这个顺序依据现有代码的适配程度；尚未用本项目的修图任务比较三者的实际效果。

本方案第一阶段采用用户本地安装的 CLI 和各自登录。直接模型 API、云端代理、MCP 服务和自动切换后端另行规划，不与此次 CLI 扩展混在一起。

## 2. 现有代码与复用范围

| 现有模块 | 当前职责 | 扩展时的处理 |
| --- | --- | --- |
| `Compositor/AI/AICodexBackend.swift` | 启动 Codex，传递文字和可选图片，生成 schema，解析计划，取消和超时 | 保留 Codex 适配器，将共用提示词和 schema 移出 |
| `Compositor/AI/AIAssistant.swift` | 对话、预览渲染、请求生命周期、文档快照、自动执行或待确认计划 | 从直接依赖 Codex 改为依赖统一后端接口 |
| `Compositor/AI/AIAssistantPanel.swift` | 输入框、图片开关、执行开关、Codex 路径和说明 | 增加后端选择、各自设置及状态说明 |
| `Compositor/AI/AIEditorCommands.swift` | `AIEditPlan v1`、命令验证、原生执行、文档过期检查 | 三种后端共用；不复制各自的执行器 |
| `CompositorTests/AIEditorCommandsTests.swift` | 原子性、撤销、过期计划、参数和格式等测试 | 保留并加入后端接入回归验证 |

当前接口支持图层选择、透明度、名称、显示状态、移动、缩放、旋转、混合模式、曝光、饱和度、黑白调整、画布缩放及撤销重做。扩展后端本身不新增修图命令。

当前画布图片来自原生渲染，长边最多 1,400 像素；大于 2,500 万像素的画布使用文字模式。执行前比较文档与历史版本，整组命令先验证，再在一个原生撤销事务中应用。这些行为应在接入时保持一致。

## 3. 拟定架构

```text
用户指令 + 当前文档信息 + 可选画布 PNG + 最近对话
                         ↓
                统一请求与后端工厂
                         ↓
          Codex / Claude Code / Gemini CLI
                         ↓
           解析结果并转换为 AIEditPlan v1
                         ↓
          共用格式、命令及文档版本检查
                         ↓
           原生编辑方法 → 画布 → 撤销/重做
```

### 统一接口

新增 `AIBackend` 协议，职责是根据请求生成计划。采用异步可取消调用，避免阻塞主线程。具体 Swift 签名在实施时结合现有并发设置确定。

建议请求对象包含：请求 ID、固定的后端及模型配置、最新指令、最近对话、文档 JSON、可选 PNG、图片尺寸和命令协议版本。

建议结果对象包含：`AIEditPlan`、实际使用的后端及可获取的模型信息。用量信息只在服务提供可靠字段时展示，并保留其单位。

每个请求独立拥有取消句柄和临时目录。取消、超时或旧请求完成后，不得向新请求交付结果。保持当前“一次只运行一个请求”的交互。

### 共用提示词与协议

将当前 `AICodexBackend.instructions` 和 `schema()` 提取为独立模块，例如 `AIPlanningContract.swift`，避免 Claude 或 Gemini 依赖 Codex 类。

命令名单、坐标单位、参数范围和不支持的功能由同一份定义生成或集中维护。其他产品功能先新增命令时，应同步维护这份协议，后续三个后端共享它。

图层名称和历史消息作为数据传递。当前文档是执行依据，历史中已经完成的操作不应重复应用。图片坐标需转换成文档像素；命令不能直接使用缩小预览的坐标。

### 共用进程管理

建议新增 `AIProcessRunner.swift`，处理进程启动、stdin、受限输出、超时、取消和临时文件清理。使用 `Process.executableURL` 和参数数组，避免通过 shell 拼接用户指令。

保留现有 180 秒请求时限和 256 KB 计划大小限制作为初始值。重试计入同一总时限。各 CLI 的退出方式单独验证，确保取消后没有遗留子进程或后续文档修改。

## 4. Claude Code 适配方案

### 已核对的官方能力

Claude Code 支持 `-p` 非交互调用，以及 `--output-format json` 配合 `--json-schema`。符合指定 schema 的结果位于外层响应的 `structured_output` 字段，不能直接把外层对象当作编辑计划。[官方说明](https://code.claude.com/docs/en/headless)

工具可用范围与免确认权限是不同设置。`--tools` 控制工具集合，`--allowedTools` 控制自动批准；后者不能代替禁用外部工具。[CLI 参数说明](https://code.claude.com/docs/en/cli-reference)

### 实施步骤

1. 新增 `AIClaudeCodeBackend.swift`，支持自动查找 CLI 和用户指定可执行文件路径。
2. 在隔离的请求目录启动非交互调用，传入共用命令 schema，解析成功、失败和 `structured_output`。
3. 首先验证文字模式，保证中文回复、图层 ID 和数值单位正确。
4. 再验证图片输入路径。优先采用目标 CLI 版本支持的结构化消息方式；在验证前不承诺与 Codex 的 `--image` 参数相同。
5. 请求仅生成编辑计划，实际修改仍由 `AIEditorCommands` 完成。验证 CLI 配置、工具、hooks、插件及 MCP 的隔离方式。
6. 对登录失效、缺少结构化结果、非零退出、取消和超时分别返回可理解的错误。

### 必须先解决的兼容问题

截至文档核对时，Claude Code 的 `--bare` 模式会跳过默认上下文发现，但不读取订阅 OAuth 或系统钥匙串凭据，需要相应 API 凭据。因此不能同时把 `--bare` 与“直接复用现有订阅登录”当作已确定的组合。[bare 模式说明](https://code.claude.com/docs/en/headless)

实施预研应确定订阅登录下可验证的配置隔离方案，并记录目标 CLI 版本。如果无法满足，先停留在未启用状态，不静默要求用户改用付费 API。API Key 模式需要另行决定产品范围。

Claude 的图像能力不等同于 CLI 图片传递已完成。需要分别验证传输方式、图片尺寸限制和实际空间判断效果。[Claude 图像能力](https://platform.claude.com/docs/en/build-with-claude/vision)

## 5. Gemini CLI 适配方案

### 已核对的官方能力

Gemini CLI 支持 `-p` 非交互调用及 JSON 输出。其 JSON 外层包含 `response` 字符串、`stats` 和可选 `error`；JSON 输出模式本身不等于模型回答已符合编辑命令 schema。[官方说明](https://geminicli.com/docs/cli/headless/)

### 实施步骤

1. 新增 `AIGeminiCLIBackend.swift`，支持自动检测和自定义可执行文件路径。
2. 解析外层 JSON 的错误状态和 `response`，再把回答解析成 `AIEditPlan`。
3. 优先使用目标版本可验证的原生 schema 约束能力；若该 CLI 未提供，则在提示中提供协议，并在本地严格检查。不能把“回答看起来像 JSON”视为成功。
4. 缺少字段、未知字段、未知命令、错误类型或不支持的版本均拒绝；随后仍执行完整命令及文档验证。
5. 对仅属于格式错误的结果，最多允许一次修正请求；不执行第一次结果，不因业务参数或文档过期而自动重试。用户需能看到重试状态。
6. 先通过文字任务，再验证受控图片输入方式及工具配置。不为读取图片开放广泛文件、shell 或浏览器权限。
7. 核对用户配置、上下文文件和扩展是否会被自动加载，建立可复现的调用配置。具体参数以实施时的文档与实际 CLI 为准。[Gemini 设置说明](https://geminicli.com/docs/cli/settings/)

## 6. 设置与用户体验

AI 设置新增后端选择：Codex、Claude Code、Gemini CLI。升级后的默认值保留 Codex，沿用既有的 Codex 路径、图片开关和自动执行开关。

各后端分别保存可执行文件路径，以及未来可支持的模型选择。显示“未安装”“已检测到”“需要登录”“版本不兼容”等状态，避免把“存在可执行文件”显示成“登录成功”。账号由相应 CLI 管理，软件不复制或分享登录凭据。

请求运行期间禁止切换后端；完成后切换时，清空当前待应用计划，并开始新的后端对话。此前聊天可作为只读历史展示，但不默认发给另一服务。用户文字、图层信息和可选画布图片会交给当前选择的服务，面板说明应随选择变化。

仅在用户显式选择对应后端后向该服务发请求。首版不自动把失败请求转发给另一后端。

## 7. 分阶段执行与完成条件

| 阶段 | 工作 | 完成条件 |
| --- | --- | --- |
| P0：接口预研 | 核对实际 CLI 版本、登录模式、配置隔离、结构化输出、图片传递和取消 | 两种新后端各有可复现的能力记录，明确支持或暂缓的部分 |
| P1：统一接口 | 提取共用协议，适配现有 Codex，增加可注入后端 | Codex 行为和现有原生编辑测试通过，无新增服务请求 |
| P2：Claude Code | 设置、文字计划解析、错误处理，再接图片 | 文字和看图任务分别验证；只有通过验证的能力进入可用状态 |
| P3：Gemini CLI | 外层解析、计划验证、有限格式修正、设置与图片 | 成功结果可执行；所有无效结果、过期文档和取消均不修改文档 |
| P4：联合验证 | 同一测试项目、切换后端、撤销/重做、保存重开 | 三后端共用命令语义，完成用户路径和版本兼容记录 |
| P5：发布 | 更新中英文说明、兼容表、变更记录和 GitHub CI | 用户决定启动并完成实现后，再按项目现有发布流程发布 |

每一阶段可独立提交，便于追踪和回退。新增 CLI 后端不会改变 `.comp` 文件格式；如果其他产品功能修改了格式，以届时项目的格式规则处理。

## 8. 验证方案

### 无账号自动测试

通过可注入后端和受控进程夹具，覆盖成功 JSON、错误外层、空结果、无效类型、截断或过大输出、登录错误、超时和取消。不在普通 CI 中依赖真实账号、实时模型或付费请求。

验证这些具有实际风险的行为：

- 不同响应包装均转换成同一种计划，并经过同一套严格检查。
- 一组有效编辑只增加一个撤销步骤；后续动作无效时整组不执行。
- 请求期间手动编辑、切换文档或撤销重做后，旧计划失效。
- 取消后立刻发新请求，旧进程和旧响应不能覆盖新请求。
- 待确认计划被丢弃或后端发生变化后，不再能应用。
- 未打开图片开关时不生成或发送图片；CLI 配置隔离确实生效。

### 真实账号人工验证

只在后续实施获准后，用测试文档和测试者自己的账号执行。使用相同画布、相同指令和相同初始文档，记录后端、模型（可获取时）、CLI 版本、成功率和耗时。

至少包含透明度、重命名、多命令组合、曝光、饱和度、看图定位、歧义问题、超出能力的请求，以及手动确认。固定数值任务应精确匹配；看图定位记录允许的误差与画布尺寸，不把格式正确视为位置正确。

同一结果随后验证撤销、重做、保存与重新打开。未进行这些任务的实测前，不宣称某后端更懂修图或视觉定位更准确。

## 10. 重新启动时的检查

用户已提出下一项优先功能为中文界面。Claude Code 与 Gemini 扩展继续暂缓；中文界面的具体本地化范围和语言切换方式在该功能实施时确定，本轮未修改界面代码。

重新开始后端扩展时，先核对新增功能是否已经改变命令列表、语言界面、请求结构或模型需求，再更新本方案。

官方文档与 CLI 会变化。实施时记录实际验证版本与能力，不只依据本文件中的日期或命令名。将未解决的登录隔离、图片传输等问题保留为明确的阶段门槛，不提前显示为已支持。
